1. 研究背景与主线

本项目最初的研究方向为双锚点终身语义 ObjectNav。在硬件升级到实车 + FAST-LIO2 + RGB-D + RTK 后，方向不变，但研究问题更具体：

核心研究问题： 机器人如何在跨室内外、跨 session 的长期部署中，可靠地维护、复用、修复语义物体记忆？

更精确地，要回答三个层次的问题：

  1. 跨锚点：室内 SLAM map frame 与室外 RTK ENU frame 不一致，如何让一条物体记忆在两个锚点下都可用？
  2. 跨 session：每次启动 FAST-LIO 的 map frame 都变，如何让记忆跨重启复用？
  3. 跨时间：物体会被挪、消失、出现，如何让记忆跟上世界变化而不是无限累积错误？

"找出去的门"等场景在演示或子能力中可能出现，但不在论文 method 章节。

2. 任务定义

2.1 形式化

每个 session 给定：

  • 目标 G = (class | instance_id | description)，例如 "找一个垃圾桶" / "找之前看过的那个垃圾桶 #042"。
  • 初始位姿 p₀。
  • 实时传感器流：fastlio2/lio_odom、rtk/fix + status、camera/rgb + depth、tf。
  • 跨 session 持久化的记忆库 M_{n-1}（首次 session 为空）。

系统输出：

  • 导航轨迹与最终结论（found / not_found / ambiguous）。
  • 本次 session 的更新后记忆库 M_n。
  • 结构化 trial events（用于审稿人复现）。

2.2 任务的多种 query 形式（按实现优先级）

优先级Query 形式对应 Layer 0 行为
P0class_name直接匹配类别（首要实现）
P1instance_id（"上次看到的那个 #042"）用记忆库 ID 直查
P2自然语言描述LLM 解析为结构化 query
P3图像/草图视觉嵌入相似度

2.3 评测指标

指标含义方向
SR找到目标的成功率↑
SPL路径长度加权成功率↑
R_speedup第 N+1 次 vs 第 1 次的时间缩减比↑（lifelong 卖点）

3. 硬件能力与设计约束

组件输出对算法的影响
FAST-LIO2map-frame 位姿 + 局部点云每次启动 map frame 不同；长走廊缓慢漂移
RTKENU-frame 位姿 + fix_type提供跨 session 不变的全局参考；室内可能失效
RGB-D (D435 等)RGB + 对齐深度深度有效 0.3–4 m，验证视点须落在此区间
开词汇检测器 (GroundingDINO 等)2D bbox + 类别 + 置信度不可信任单次检测，需要多帧投票
视觉嵌入 (CLIP/DINO)每个物体的视觉特征向量instance 级匹配的关键
必须 Week 0 / W1 验证的硬件假设：
  • FAST-LIO2 在你们目标场景的漂移率（每分钟？每 100 米？）
  • RTK 在实验楼室内的真实表现（完全无信号 vs 靠窗 FLOAT vs 深处 NO_FIX）
  • RGB-D 在不同光照下的深度噪声
这些数字决定算法参数（窗口长度、协方差阈值、验证视点距离）。没有这些数字之前不要调参，会白调。

6. 核心子算法详解

A. Anchor Manager（Layer 2）

基础设施 所有跨锚点操作的几何前提。

输入 / 输出

  • 输入：(pose_map_t, pose_enu_t, rtk_quality_t, lio_quality_t) 流
  • 输出：T_ENU←map (SE(3)) + 6×6 协方差 + AnchorHealth

原理

RTK FIXED 时，每个时刻得到一对 ground-truth 配对 (p_map_t, p_enu_t)。两个 frame 满足：

penut = TENU←map · pmapt + ε

在滑动窗口内求带权最小二乘（Kabsch / Horn 闭式解）：

T̂ = arg minT Σt wt ‖ T · pmapt − penut ‖²

关键设计点

  • 窗口长度自适应（基于残差中位数 + RTK 稳定性）。
  • 权重 w_t = 1 / σ_rtk(t)²，从 NavSatFix 协方差读取（不要硬编码）。
  • 当窗口内可信配对 < N_min，输出 UNAVAILABLE。
  • RTK 长期不可用时，记录 LIO 时钟下的版本号，使跨 session 复用时仍能事后对齐。
注：你们现有 G60 + 多 session bag 数据可立刻拿来离线验证 Anchor Manager 在最差 GPS 条件下的工作。如果 G60 都能给出可解释的协方差，RTK 升级后必然更稳。

B. 观测路由器（Layer 3）

桥接 单帧观测如何归属到锚点。

def route_observation(obs, lio_q, rtk_q, anchor_transform):
    # 1. 估算两种锚点下的位置 + 协方差
    pose_in_map, cov_in_map = obs.pose_map, obs.cov_map
    pose_in_enu, cov_in_enu = project_to_enu(obs, anchor_transform)

    # 2. 比较不确定性
    if rtk_q == "FIXED" and trace(cov_in_enu) < trace(cov_in_map):
        return Observation(anchor="enu", pose=pose_in_enu, cov=cov_in_enu)
    if lio_q.recent_drift < THRESH:
        return Observation(anchor="map", pose=pose_in_map, cov=cov_in_map)
    return None  # 双低质量, 丢弃; 这是设计上的常态, 不是 bug

关键

  • 检测协方差 + 深度噪声 + 位姿协方差 + 锚点变换协方差，必须全部传播（用 Jacobian）。
  • "丢弃低质量观测"的策略要在论文里做 ablation：太严会丢召回，太松会污染记忆。

C. 跨锚点物体匹配（Layer 4）

★ 论文核心 解决 "this is the same object as #042" 的判断。

匹配概率

P(obs = m) ∝ Pclass(obs, m) · Pposition(obs, m) · Pappearance(obs, m)
  • Pclass：硬约束（类别必须一致）或类别相似度
  • Pposition：跨锚点投影后的 Mahalanobis 距离 → χ² → 概率
  • Pappearance：CLIP / DINOv2 嵌入余弦相似度

核心难点：跨锚点 Pposition

# obs 在 ENU 下:   pose_obs_enu, cov_obs_enu
# m   在 map 下:   pose_m_map,   cov_m_map
# 用 Anchor Manager 给的 T_ENU←map 投影 m 到 ENU:
pose_m_enu = T_ENU_map @ pose_m_map
cov_m_enu  = J @ cov_m_map @ J.T  +  cov_transform   # 协方差传播!

# 两者现在都在 ENU 下, 算 Mahalanobis:
delta        = pose_obs_enu - pose_m_enu
combined_cov = cov_obs_enu + cov_m_enu
mahal        = delta.T @ inv(combined_cov) @ delta
P_position   = chi2.sf(mahal, df=3)

决策

  • 选概率最大的候选 m*，若 P(obs = m*) < τ_match，标记为 NEW。
  • NEW 候选若 Pclass 一致 + 附近有 missing 同类记忆，写 possible_relocation_of(new, old) 边（不强行 merge）。

两个独立信念

信念含义衰减率
P_existence物体仍在 (没消失)类别相关 λ_e
P_location位置仍正确 (没被挪)类别相关 λ_l
P_existence(t + Δt) = P_existence(t) · exp(− λ_e · Δt)
P_location(t + Δt) = P_location(t) · exp(− λ_l · Δt)
  • 墙、灭火器、消防栓：λ 很小（几乎不变）
  • 椅子、垃圾桶：λ 中等
  • 杯子、书、文件：λ 较大

类别相关的衰减率可从 lifelong 数据 fit，本身就是论文一个 ablation/分析点。

E. 信念更新（Layer 5 子算法）

看到时（Bayesian update + Kalman 融合）

if match.is_new:
    create_new_memory_object(obs)
else:
    m = match.existing
    # Kalman update on position
    K        = m.cov @ inv(m.cov + obs.cov)
    m.pose   = m.pose + K @ (obs.pose - m.pose)
    m.cov    = (I - K) @ m.cov
    # Bayesian update on existence
    m.P_existence = bayes_update(m.P_existence, evidence="seen")
    m.P_location  = bayes_update(m.P_location,  evidence="confirmed")
    m.last_seen_t  = now
    m.observation_count += 1

应该看到但没看到时

def on_expected_but_not_seen(m):
    # 机器人路过 m 的视野却没检测到
    m.P_existence = bayes_update(m.P_existence, evidence="missed")
    m.miss_count += 1
    if m.P_existence < 0.3 and m.state == REUSABLE:
        m.state = STALE
    if m.P_existence < 0.1:
        m.state = SUSPECT_MISSING

验证视点

  • 验证物体是否真消失：导航到一个该物体应该可见的视点
  • 视点必须满足：RGB-D sweet spot（0.5–3 m）+ 不在障碍物里 + 朝向物体 + Nav2 可达
  • 失败时执行 yaw 扫描（±25°）作为第二次确认（你 objectnav_core 里已有此逻辑）

F. 主动探索/验证调度（Layer 6）

规划层：在探索新区域和复查/验证记忆之间做决策。

候选集

  • 新 frontier（探索未知）
  • 所有 stale / suspect_missing 物体（验证）
  • 目标类的所有 reusable 物体（如果与当前 query 匹配）

评分

score(c) = α · Prelevant(c) + β · Igain(c) − γ · cost(c) − δ · revisit(c)

对于记忆物体的复查紧迫度：

urgency(m) = (1 − P_existence(m)) · importance(class) / (1 + path_cost(m))

权重 α, β, γ, δ 可以静态调，也可以做成 contextual：当 ObjectNav goal 已锁定记忆中的物体时，α 大；当记忆库与 query 都无匹配时，β 大（鼓励探索）。

13. 算法数学推导

本章把前面 7 层架构里的每一个核心算法从问题陈述一步步推到可实现公式。所有推导自洽，可直接对照写入论文 Method 章节。

D.0 记号与基础设定

记号含义
p ∈ ℝ³3D 位置向量（粗体竖列）
pFX点 X 在坐标系 F 下的位置
TB←A ∈ SE(3)从 A 系到 B 系的刚体变换，作用在齐次坐标上
R ∈ SO(3), t ∈ ℝ³变换的旋转与平移分量
Σ协方差矩阵
Inn×n 单位阵
ε ∼ 𝒩(0, Σ)零均值高斯噪声
tr(·)矩阵迹

整个系统的随机变量在同一高斯近似框架下推导：每个位置量都带一个均值和协方差，每个非线性变换都用一阶 Jacobian 传播协方差（Extended Kalman 思路）。

D.1 Anchor Manager: T̂ENU←map 的闭式解

问题陈述

设滑动窗口内有 N 对时间戳对齐的配对：

{ (pimap, pienu) }i=1…N,   pienu = R pimap + t + εi,   εi ∼ 𝒩(0, Σi) (D.1.1)

求最优旋转 R ∈ SO(3) 和平移 t ∈ ℝ³，最小化带权重残差：

J(R, t) = ∑i wi ‖ R pimap + t − pienu ‖² (D.1.2)

实际中 wi = 1/σi²（标量近似）；完整版用 Σi−1 加权，原理相同。

第 1 步：对 t 求导消去平移

对 (D.1.2) 求 ∂J/∂t = 0：

∑i wi ( R pimap + t − pienu ) = 0

令加权质心：

p̄map = (∑wi pimap) / (∑wi),   p̄enu = (∑wi pienu) / (∑wi)

得到：

t = p̄enu − R p̄map (D.1.3)
第 2 步：去中心化，问题降为纯旋转

令 qimap = pimap − p̄map，qienu = pienu − p̄enu，代回 (D.1.2)：

J(R) = ∑i wi ‖ R qimap − qienu ‖²

展开 ‖·‖² 后，与 R 相关的项只剩交叉项：

arg maxR   tr( R H ),   其中 H = ∑i wi qimap ( qienu )⊤ (D.1.4)
第 3 步：用 SVD 求解

对 3×3 矩阵 H 做 SVD：H = U D V⊤。最优旋转为：

R̂ = V S U⊤,   S = diag(1, 1, det(V U⊤)) (D.1.5)

中间的 S 是为了避免 SVD 给出反射解（行列式 −1）。这就是经典的 Kabsch–Umeyama 算法。

第 4 步：回代得到平移

把 R̂ 代入 (D.1.3) 得到 t̂。最终：

T̂ENU←map =
R̂t̂
0⊤1
 (D.1.6)

意义：这是 SE(3) 上对齐两个点云的解析解，无需迭代。在每个新数据点到来时只需更新加权质心与 H 矩阵（O(N) 内存或滑动窗口 O(1) 更新），SVD 复杂度恒为 O(1)（3×3 矩阵）。非常适合在线运行。

D.2 锚点变换的协方差估计

光有 T̂ 不够，下游所有匹配都需要 cov(T̂)。我们用最大似然 + 残差经验估计：

第 1 步：定义在 se(3) 上的小扰动

设真值 T*，估计值 T̂。它们之间的差异用李代数小扰动 ξ ∈ ℝ⁶（前 3 维平移，后 3 维旋转向量）表示：

T* = exp( [ξ]∧ ) T̂,   ξ ∼ 𝒩(0, ΣT ∈ ℝ6×6) (D.2.1)
第 2 步：残差与信息矩阵

第 i 个配对的预测残差：

ri(ξ) = exp([ξ]∧) T̂ pimap − pienu

对 ξ 在零点处线性化，Jacobian：

Ji = ∂ri/∂ξ |ξ=0 = [ I3   −[R̂ pimap + t̂]× ] (D.2.2)

[·]× 是叉乘矩阵（反对称矩阵）。这是 SE(3) 上点变换 Jacobian 的标准形式。

第 3 步：协方差 = 逆信息矩阵

由高斯-牛顿信息矩阵：

ΣT ≈ ( ∑i Ji⊤ Σi−1 Ji )−1 (D.2.3)
第 4 步：用经验残差校正

(D.2.3) 在模型完美时成立。实际中 LIO 有未建模漂移，建议乘上经验残差因子：

σ̂² = ( ∑i wi ‖ri(0)‖² ) / ( 3N − 6 ),   ΣTfinal = σ̂² · ΣT (D.2.4)

3N 个残差自由度减去 6 个估计参数（SE(3) 的 6 维）。

这就是为什么 G60 数据也能离线验证 Anchor Manager：噪声越大，σ̂² 越大，ΣT 越大，下游匹配阈值越宽松，系统会自动"知道自己不准"，这正是协方差感知的价值。

D.3 单帧观测的位置协方差链

从相机看到一个物体，到这个物体在 map / ENU 锚点下的位置 + 协方差，要经过4 次坐标变换 + 4 次协方差传播。

链条总览

D.3.2 → 机器人基座系

Tbase←cam 来自标定，假设已知且无噪声：

pbase = Rbase←cam pcam + tbase←cam,   Σbase = Rbase←cam Σcam Rbase←cam⊤
D.3.3 → map 锚点系（关键：机器人位姿也带噪声）

设机器人位姿 Tmap←base 有协方差 Σpose ∈ ℝ6×6（来自 FAST-LIO 输出）。点的变换为：

pmap = Rmap←base pbase + tmap←base

两个噪声源：点本身的 Σbase 和位姿的 Σpose。位姿对点位置的 Jacobian（用 D.2 的同形式）：

Jpose = [ I3   −[ R pbase ]× ]

总协方差：

Σmap = Rmap←base Σbase Rmap←base⊤  +  Jpose Σpose Jpose⊤ (D.3.3)
D.3.4 → ENU 锚点系（再加 T̂ 的协方差）

同上，但这次 T̂ENU←map 的协方差 ΣT 来自 D.2：

penu = R̂ENU←map pmap + t̂ENU←map
Σenu = R̂ENU←map Σmap R̂ENU←map⊤  +  JT ΣT JT⊤ (D.3.4)

意义：Σenu 严格 ≥ Σmap（额外加了 ΣT）。这是物理直觉：把观测投到 ENU 锚点上一定不会比留在 map 锚点更确定。这个不等式直接驱动了 D.4 的路由决策。

D.4 观测路由的最小迹判据

观测应该归属到哪个锚点？我们用"哪个锚点下不确定性更小"作为决策。"不确定性"用矩阵迹度量（也可以用行列式，但迹计算便宜）。

定义：

Umap = tr( Σmap ),   Uenu = tr( Σenu )

决策规则（结合锚点健康度）：

anchor = { ENU,  if RTK = FIXED ∧ Uenu < Umap   MAP,  else if driftLIO < τdrift   DROP,  otherwise } (D.4.1)

注解：

  • 由 D.3 的不等式，Uenu < Umap 实际上意味着原始观测离 RTK 锚点的"参考点"很近（cov 投影后没放大太多）。
  • RTK FIXED 是必要条件但不充分；FIXED 状态下 ΣT 仍可能很大（窗口短、配对少）。
  • DROP 是设计上的常态，不是 bug。

D.5 跨锚点物体匹配的 Mahalanobis 推导

新观测 obs（已带锚点归属）和记忆物体 m（也已带锚点归属）做匹配。难点：两者可能在不同锚点下。

第 1 步：投到共同锚点（不妨投到 ENU）

若 m 在 map 下：

μmenu = R̂ENU←map μmmap + t̂ENU←map
Σmenu = R̂ Σmmap R̂⊤ + JT ΣT JT⊤ (D.5.1)

obs 已在 ENU 下：μobsenu, Σobsenu。

第 2 步：差向量分布

假设 obs 和 m 独立（合理：一个是当前传感器读数，一个是历史记录），差向量：

Δ = μobsenu − μmenu ∼ 𝒩( 0, ΣΔ ),   ΣΔ = Σobsenu + Σmenu (D.5.2)

"如果两者真是同一个物体"则 Δ 应零均值。

第 3 步：Mahalanobis 距离 → χ² → 概率
d²M = Δ⊤ ΣΔ−1 Δ

当假设成立时，d²M ∼ χ²(3)。所以：

Pposition(obs = m) = 1 − Fχ²(3)( d²M ) (D.5.3)

Fχ²(3) 是自由度 3 的 χ² 累积分布。distance 越小，概率越接近 1；distance 大时迅速衰减。

第 4 步：三因子融合
P(obs = m) = Pclass(obs, m) · Pposition(obs, m) · Pappearance(obs, m) (D.5.4)

其中：

  • Pclass：硬约束 (0/1) 或 fine-grained 类别相似度
  • Pappearance = max(0, <eobs, em> / (‖e‖²))：CLIP/DINO 嵌入余弦相似度
第 5 步：决策

对所有候选 m ∈ memory，找 m* = arg max P(obs = m)：

match = { m*,  if P(obs = m*) ≥ τmatch   NEW,  otherwise } (D.5.5)

τmatch 是 ablation 关键参数；论文里要 sweep 不同值看 precision/recall trade-off。

D.6 多证据贝叶斯融合 (log-odds)

D.5 是位置 + 视觉 + 类别的瞬时匹配。但对一条记忆 m 本身的"它还存在吗"信念，需要积累多次证据。

第 1 步：定义 log-odds

对随机事件 E（"物体 m 还存在"），定义：

ℓ(E) = log [ P(E) / (1 − P(E)) ] (D.6.1)

逆变换：P(E) = sigmoid( ℓ(E) ) = 1 / (1 + e−ℓ)。

第 2 步：贝叶斯规则的 log-odds 形式

对单个证据 ei：

ℓ(E | e1, …, ek) = ℓ(E) + ∑i log [ P(ei | E) / P(ei | ¬E) ] (D.6.2)

假设证据条件独立（典型 Naive Bayes 假设，工程上够用）。这就是 log-odds 形式的关键优势：多个证据线性可加。

第 3 步：每类证据的 log-likelihood ratio
证据取值LLR 估计
"应见到 m 但没见到"1 次log [ P(miss | E) / P(miss | ¬E) ] = log [ pmiss / 1 ] (负数, 减信念)
"看到了 m"（匹配概率 P(obs=m)）P(obs=m)log [ P(obs=m | E) / P(obs=m | ¬E) ] (正数, 加信念)
"附近出现同类 NEW 物体"1 次log [ P(new | relocated_m) / P(new | ¬E) ] (中性偏负)

pmiss 是检测器漏检率，可以从 calibration 数据估计。

D.7 位置 Kalman 融合

D.6 更新的是存在性信念。当 D.5 决定 obs 匹配上某个 m 时，还要更新 m 的位置。这是经典 Kalman update。

先验：m 的位置 μm, Σm。观测：μobs, Σobs（均已投到 m 的锚点系下）。

Kalman 增益
K = Σm ( Σm + Σobs )−1 (D.7.1)
后验
μm+ = μm + K ( μobs − μm )
Σm+ = ( I − K ) Σm (D.7.2)

物理意义：

  • 若 obs 很准（Σobs 小），K → I，记忆几乎采纳新观测。
  • 若 obs 很噪（Σobs 大），K → 0，记忆几乎不动。
  • 多次观测后 Σm 持续收缩——记忆位置越来越准。

D.8 信念衰减: hazard rate 推导

没有任何观测时，记忆的存在性信念应该随时间衰减。为什么是指数衰减？

第 1 步：假设恒定 hazard rate

设物体在 [t, t + dt] 内消失的条件概率为 λ · dt（λ 是常数 hazard rate）。则存活函数满足：

P_existence(t + dt) = P_existence(t) · ( 1 − λ · dt )
第 2 步：取连续极限

整理为微分方程：

dP/dt = − λ · P  ⟹   P(t) = P(0) · e−λt (D.8.1)
第 3 步：类别相关 λ
物体类别典型 λ (1/天)半衰期
墙、消防栓、灭火器10−4~19 年
办公椅、垃圾桶10−2~70 天
杯子、文件、个人物品10−1~7 天

λ 可手设，更好是从训练数据 fit：

λ̂ = arg maxλ ∑(t, observed_or_not) log L(λ; data)

这就是 survival analysis 的 MLE，论文一个 ablation/分析点。

D.9 应见而未见时的贝叶斯更新

这是区分"感知失败"和"世界变化"的核心。

第 1 步：建模观测模型

设记忆物体 m 在视野内，机器人此时进行了一次 detection 但 m 没出现。定义：

  • P(miss | exists) = pfn：检测器漏检率（false negative rate）
  • P(miss | ¬exists) = 1：物体不存在则一定看不到
第 2 步：贝叶斯更新
Pexist+ = Pexist · pfn  /  ( Pexist · pfn + (1 − Pexist) · 1 ) (D.9.1)
第 3 步：log-odds 形式 (推导更直观)
ℓ+ = ℓ + log( pfn )   (注意 pfn < 1, log 为负) (D.9.2)
第 4 步：连锁触发状态机
P_exist 阈值                       状态
─────────────                     ─────
≥ 0.7                              reusable
0.3 – 0.7                          stale
0.1 – 0.3                          suspect_missing  → 触发主动 yaw 扫描
< 0.1                              missing          → 等待 NEW 同类做 relocation

pfn 越小（检测器越好），单次 miss 的衰减越剧烈；pfn 越大，需要多次 miss 才能确认。

这就是为什么不能用硬阈值：硬阈值在 pfn 改变时全崩，贝叶斯更新自动适应检测器质量。

D.10 决策评分函数的设计动机

规划层选择"下一步去哪"。候选集 C 包括 frontier + 待验证记忆物体。评分函数：

score(c) = α · Prelevant(c) + β · Igain(c) − γ · cost(c) − δ · revisit(c) (D.10.1)

各项的来源与单位

项定义单位
Prelevant(c)该候选满足当前 ObjectNav goal 的概率[0, 1]
Igain(c)访问 c 预计揭示的未知面积m²
cost(c)从当前位姿到 c 的 A* 路径长度m
revisit(c)历史访问惩罚（计数或频率）无量纲

对记忆物体 m 的 Prelevant

结合 D.9 的 P_existence 与匹配度：

Prelevant(m | goal) = Pexistence(m) · Pmatch(m, goal) (D.10.2)

对记忆物体的 urgency（用于待验证排序）

urgency(m) = (1 − Pexistence(m)) · importance(class(m)) / (1 + cost(m)) (D.10.3)

P_existence 越低（越不确定）+ 类别重要性越高 + 路径越短，越紧急复查。

权重调度

α, β 随时间动态调整：

α(t) = sigmoid( (t − t0) / τ ),   β(t) = 1 − α(t)

意义：早期 explore-heavy（β 大），后期 exploit-heavy（α 大）。τ 是切换时间尺度（建议 30-60 秒）。

D.11 端到端: 一帧观测的完整推导链

把 D.1–D.10 串起来，演示一帧 RGB-D 图来后系统完整的数学流程：

┌─ 输入 ─────────────────────────────────────────────────┐
│ frame_t = {                                            │
│   rgb, depth, camera_info,                              │
│   pose_map (FAST-LIO + cov),                            │
│   rtk: (lat, lon, alt, fix_type, cov)                   │
│ }                                                       │
└─────────────────────┬───────────────────────────────────┘
                      ▼
[Step 1] Anchor Manager 更新 (用 D.1, D.2)
   if rtk.fix_type == FIXED:
      append (pose_map_t, pose_enu_t) to window
      recompute T̂, Σ_T via (D.1.5), (D.2.3-4)

                      ▼
[Step 2] 检测 (Layer 1, 现成检测器)
   for each bbox in GroundingDINO(rgb):
      d = depth[bbox.center]
      p_cam, Σ_cam ← (D.3.1)

                      ▼
[Step 3] 协方差链 (用 D.3.2-4)
   p_base, Σ_base ← apply T_base_cam
   p_map,  Σ_map  ← apply pose_map, propagate Σ_pose  (D.3.3)
   if T̂ available:
      p_enu, Σ_enu ← apply T̂, propagate Σ_T          (D.3.4)

                      ▼
[Step 4] 观测路由 (用 D.4)
   anchor ← min trace decision (D.4.1)
   if anchor == DROP: skip frame
   else: emit Observation(anchor, μ_obs, Σ_obs, embed)

                      ▼
[Step 5] 跨锚点匹配 (用 D.5)
   for each m in memory:
      project m to obs's anchor if needed (D.5.1)
      compute P(obs = m) via D.5.2-4
   m* = argmax P(obs = m)
   if P(obs = m*) ≥ τ_match: match = m*
   else: match = NEW

                      ▼
[Step 6] 记忆更新 (用 D.6, D.7)
   if match is NEW:
      create new memory object, initialize with (μ_obs, Σ_obs, embed)
      # 检查是否触发 relocation
      for m' in nearby missing same-class:
         add edge possible_relocation_of(NEW, m')
   else:
      # Kalman 位置融合 (D.7)
      K ← (D.7.1); update m.μ, m.Σ via (D.7.2)
      # 贝叶斯存在性更新 (D.6)
      m.ℓ ← m.ℓ + log(P(obs|exists) / P(obs|¬exists))
      m.last_seen_t ← t

                      ▼
[Step 7] 对所有 "应见而未见" 的 m 更新 (用 D.9)
   for each m within current view frustum:
      if m not matched this frame:
         m.ℓ ← m.ℓ + log(p_fn)
         if sigmoid(m.ℓ) < threshold:
            transition state (reusable → stale → suspect_missing)

                      ▼
[Step 8] 时间衰减 (用 D.8)
   for all m (low-frequency, e.g., every 10s):
      m.P_existence ← m.P_existence · exp(-λ_class * Δt)

                      ▼
[Step 9] 规划层挑下一目标 (用 D.10)
   candidates = frontiers ∪ {m: state ∈ {stale, suspect_missing, reusable_target}}
   for c in candidates:
      compute score(c) via (D.10.1-3)
   goto argmax score(c)

                      ▼
[Step 10] 持久化
   写 SQLite: observation, decision, anchor_transform, trial_event

整条链的关键性质：

  1. 每个状态量都带协方差，整条链没有任何硬阈值的"如果距离 < X 米则匹配"之类的不可解释设计。
  2. 系统在低质量传感器下自动降级（DROP / 较大 Σ / 衰减更快），无需特例代码。
  3. 每个步骤的中间结果都可持久化、可回放、可可视化，论文的失败案例分析有据可查。
  4. 大模型只在 Step 2 出现（检测器），替换检测器不需要改其他任何一步。
论文叙事支撑： 这一节即是论文 Method 章节的脊柱。每个子节 (D.1–D.10) 对应论文里一个 subsection，D.11 对应论文里的 "Algorithm 1" 伪代码。Method 写作的"难"主要在这里——一旦推导清晰，行文反而是体力活。

14. 待用户确认的设计选项

本架构留下了几个需要你确认的选项；在 W1 开工之前应明确。

  1. "找门"的位置：完全不在论文中？还是作为跨建筑 ObjectNav 的子能力出现？（默认假设：完全不在 method 中。）
  2. 主实验场地：实验楼室内 + 周边户外 / 多个房间纯室内 / 跨建筑？这影响"双锚点"是否真正发挥作用。
  3. 物体选择：实验放置（椅子/垃圾桶/标记物等）还是环境固有（桌子/灭火器/打印机）？
  4. Lifelong 时间尺度：可做的部署频率（1 周 5 次 / 2 周 10 次 / 1 月持续）？
  5. 实验楼 RTK 实际表现：完全无信号 / 靠窗 FLOAT / 深处 NO_FIX？

这些回答会影响 W1-W6 的具体实施细节（特别是 Anchor Manager 的参数 + 物体类别白名单 + 部署节奏）。
