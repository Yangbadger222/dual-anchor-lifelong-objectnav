# Design Doc: Phase 1A Visual Experiment Report

Date: 2026-05-24  
Owner: Codex  
Status: Implemented

## Goal

Create a static Chinese HTML report that visualizes the current Phase 1A deterministic ObjectNav experiment results and clearly explains the workflow.

## Non-Goals

- This report does not run ROS 2, Nav2, detectors, or robot adapters.
- This report does not claim real-robot performance.
- This report does not replace the SQLite memory database or JSON artifacts.
- This report does not introduce a frontend framework or local web server.

## Background

The current Phase 1A CLI runner writes artifacts under `runs/phase1a/latest/`:

- `memory.sqlite`
- `summary.json`
- `memory_snapshot.json`
- `events.jsonl`

The user asked for an HTML file that visualizes the experiment data and clearly shows the current workflow.

## System Boundary

Owned by this report:

- human-readable visualization of run metrics
- workflow explanation for Phase 1A
- memory-state and relocation visualization
- artifact manifest

Outside this report:

- trial execution logic
- SQLite schema changes
- ROS 2 integration
- detector or VLM integration

## Inputs and Outputs

| Direction | Name | Type / Format | Notes |
|---|---|---|---|
| Input | Phase 1A summary | `runs/phase1a/latest/summary.json` | Run metrics and artifact manifest |
| Input | Memory snapshot | `runs/phase1a/latest/memory_snapshot.json` | Object states and relocation relation |
| Input | Event log | `runs/phase1a/latest/events.jsonl` | Trial event count and event trail |
| Output | Visual report | `runs/phase1a/latest/report.html` | Static Chinese HTML file |

## Interfaces

Open the report directly in a browser:

```bash
open runs/phase1a/latest/report.html
```

No server is required.

## Data Flow

1. Read the latest Phase 1A artifact values from `summary.json`, `memory_snapshot.json`, and `events.jsonl`.
2. Render key metrics as static HTML charts and tables.
3. Render the ObjectNav workflow and memory-state flow as HTML/CSS diagrams.
4. Save the report next to the experiment artifacts.

## Failure Modes

| Failure | Detection | Recovery / Mitigation |
|---|---|---|
| Report data drifts from artifacts | Compare embedded values against JSON files | Regenerate the report after rerunning CLI |
| HTML navigation breaks | Parse anchors with `HTMLParser` | Fix missing ids or hrefs |
| Report is mistaken for real-robot result | Report title and caveats state deterministic simulation | Keep ROS/real-robot notes visible |

## Verification Plan

- Parse the HTML with Python `HTMLParser`.
- Confirm internal navigation anchors resolve.
- Confirm the report contains all four trial ids.
- Confirm the report contains the latest object states from `memory_snapshot.json`.
- Confirm the report file exists under `runs/phase1a/latest/report.html`.

## Research Relevance

The report gives the project a readable experiment artifact that can later inform baseline comparisons, paper figures, and handoff discussions.

## Open Questions

- Should future reports be generated by a CLI command instead of manually rendered from the current artifacts?
- Should we add plots for per-event timelines once event payloads become richer?
