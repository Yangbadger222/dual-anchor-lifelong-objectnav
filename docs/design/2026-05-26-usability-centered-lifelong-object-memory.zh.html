可用性中心长期物体记忆算法

Usability-Centered Lifelong Object Memory for ObjectNav。核心不再是证明物体是否客观存在， 而是判断一条记忆是否还值得被导航系统使用。

1. 研究定位：从“坐标对齐”转向“记忆可用性”

之前的双锚点路线把 RTK / LIO map 对齐、协方差传播、跨锚点匹配作为主要贡献。 这条路线可以成为扎实的系统工程，但算法创新偏弱，而且室内 RTK、SLAM covariance、RGB-D 观测质量都不稳定。

新的主问题： 机器人在长期 ObjectNav 中，如何让不可靠、过期、不可验证的物体记忆自动退出导航决策， 同时避免把真实物体因为一次坏观测误删？

因此，论文主线不再是“我们能证明物体存在/消失”，而是： 在真实传感器不可靠时，维护对导航有用的长期物体记忆。

2. 问题定义：Object Memory 的目标不是世界真相，而是任务可用性

真实机器人会遇到几类长期记忆污染：

感知污染 误检、漏检、bbox 抖动、深度中心落到背景、玻璃或边缘飞点。
环境变化 物体被移动、拿走、遮挡，或者新障碍物让旧验证点不可达。
定位漂移 SLAM 位姿和 anchor covariance 不可靠，旧位置投影可能漂移。

这些问题无法靠单个可靠性分数解决。我们把每条记忆拆成三个 belief： 

P_existence        物体可能仍然存在
P_location_valid   旧位置是否仍可信
P_usable           这条记忆是否值得参与 ObjectNav 决策

导航决策主要使用 P_usable。一条记忆可以“也许还存在”，但因为位置冲突、 长期遮挡或路径不可达而不再可用。

3. 状态机：允许不确定，不强行删除

raw detection
  -> tracklet
  -> candidate
  -> confirmed
  -> reusable
  -> stale
  -> location_conflict / occluded / unverifiable
  -> retired
  -> revived by positive evidence

missing 不是常规终态。真实 RGB-D 下很难可靠证明物体消失。 更常见、更安全的做法是把低可用性记忆 retire/archive， 让它退出默认 ObjectNav 决策，但保留证据日志，未来重新观察到时可以恢复。

状态含义导航行为
candidate短期证据支持，但还不能长期复用不作为默认目标
reusable位置、可达性、可用性都足够高可被 trust 或 verify
location_conflict旧位置出现冲突证据优先 verify 或 search，不直接 trust
occluded旧位置被遮挡，无法确认短期保留，长期降低 usability
unverifiable长期无法获得诊断性证据降低 usability
retired不再值得默认参与导航默认隐藏，可被重新观察恢复

4. 七步算法：每一步做什么、怎么做

Step 1 · 延迟出生

做什么阻止孤立误检直接写入长期记忆。

怎么做检测先进入短期 tracklet buffer。只有当它相对 clutter 假设持续积累证据时，才变成 candidate。

L_h(t) = L_h(t-1)
       + log p(z_t | H_object, h)
       - log p(z_t | H_clutter)

如果同类物体靠得很近，或 bbox 跳动导致关联不确定，就保留为 ambiguous cluster， 不强行更新长期 memory。

Step 2 · 延迟晋升

做什么防止 candidate 太早成为 reusable memory。

怎么做要求多帧/多视角一致、定位健康可接受、验证视点可达，必要时完成一次诊断性验证。

如果 SLAM health 差、anchor 不可靠、深度异常，即使观测看起来像目标，也只能存弱证据，不能 promote 或 merge。

Step 3 · 证据分级

做什么把“没看到”拆成不同证据类型，而不是直接当作物体消失。

证据含义更新倾向
POSITIVE重新看到目标提高三种 belief
FREE旧位置核心区域被保守证明为空降低 location_valid
NON_CONFIRMATION尝试看了，但证据不足弱降低 usable
OCCLUDED旧位置前方被挡住存在不变，可用性随持续遮挡下降
UNKNOWN深度坏、姿态不准、ray 不足单次不更新，多次可降低 usable
ACCESS_BLOCKED验证点不可达或路径被堵降低 usable

Step 4 · 可用性更新

做什么用事件驱动 hazard 更新 P_usable，不是手写每个类别半衰期。

lambda_u =
  lambda_base
  + lambda_conflict
  + lambda_access
  + lambda_scene_change
  + lambda_non_confirmation

P_usable(t + dt) = P_usable(t) * exp(-lambda_u * dt)

类别只做粗先验，例如 structural / furniture / movable / unknown。 真正让记忆退休的是事件：反复不可确认、路径不可达、场景变化、位置冲突。

Step 5 · 有限预算决策

做什么在当前 episode 预算内决定 trust、verify、search 还是 retire。

P_v = P_existence * P_location_valid * P_usable

E[C_trust] =
  P_v * D_nav
  + (1 - P_v) * (D_nav + C_fail + E[C_search | failed])

成本统一用米或秒。剩余预算只作为可行性约束和诊断信号，不在每个分支里直接截断；否则低预算会把失败分支变成“便宜失败”，诱导机器人无脑相信低可信旧位置。

Step 6 · 路径代价缓存与失效

做什么避免每次对全库跑 planner，但在地图变化时不相信旧缓存。

inflated_changed_region =
  dilation(changed_cells,
           robot_radius + safety_margin + costmap_inflation_radius)

path_tube =
  dilation(planned_path,
           robot_radius + tracking_error_margin)

如果 inflated_changed_region 与 path_tube 相交， 或路径 tube 内 cost 明显上升，就刷新 finalist 的路径代价。 这能处理“箱子本体没压住中线，但 inflation layer 已经堵路”的真实 Nav2 问题。

Step 7 · 顺路验证

做什么利用去目标 A 的路上顺便维护目标 B 的 memory。

怎么做如果验证 B 的额外代价很小，就加入转头、侧视或短 detour。

if extra_cost(B along route) < opportunistic_budget:
    verify B without changing the primary task

6. 算法推导

5.1 延迟出生的序贯似然比

对一个局部假设 h，每条观测 z_t 有两种解释： 它来自真实物体，或者来自 clutter / false positive。

\[ L_h(t) = \sum_{\tau=1}^{t} \log \frac{p(z_\tau \mid H_{\mathrm{object}}, h)} {p(z_\tau \mid H_{\mathrm{clutter}})} \]

当 L_h 越过上边界 A 时，候选出生；越过下边界 B 时丢弃。 这比固定 N 帧或固定 IoU 阈值更可解释，因为边界对应的是可接受的误晋升/误拒绝风险。

5.2 可用性 belief 的拆分

单个存在概率不够，因为物体可能存在但不可用。定义：

\[ b_m = (p_e, p_l, p_u) \]

其中 p_e 是存在概率，p_l 是位置有效概率， p_u 是导航可用性。ObjectNav 的决策主要使用：

\[ P_v(m) \approx p_e \cdot p_l \cdot p_u \]

这不是说三者真实独立，而是一个保守的可实现近似：任何一个维度低，记忆都不应该被轻易 trust。

5.3 事件驱动 hazard

不使用手写类别半衰期表。可用性衰减由事件驱动：

\[ \lambda_u(m,t) = \lambda_{\mathrm{base}} + \lambda_{\mathrm{conflict}} + \lambda_{\mathrm{access}} + \lambda_{\mathrm{scene}} + \lambda_{\mathrm{nonconfirm}} \]
\[ p_u(t+\Delta t) = p_u(t)\exp(-\lambda_u(m,t)\Delta t) \]

如果 memory 长期不可确认、路径受阻、局部场景变化，p_u 会下降。 这不会断言物体消失，只会让该记忆退出默认导航决策。

5.4 有限预算期望成本

用户提出的 trust 期望成本应成为正式公式：

\[ \mathbb{E}[C_{\mathrm{trust}}] = P_v D_{\mathrm{nav}} + (1-P_v)\left( D_{\mathrm{nav}} + C_{\mathrm{fail}} + \mathbb{E}[C_{\mathrm{search}}\mid \mathrm{failed}] \right) \]

对 verify 和 search：

\[ \mathbb{E}[C_{\mathrm{verify}}] = D_{\mathrm{verify}} + \sum_o P(o\mid \mathrm{verify},m) \mathbb{E}[C_{\mathrm{after}}(o)] \]
\[ \mathbb{E}[C_{\mathrm{search}}] = C_{\mathrm{default\_search}} \]

最终选择：

\[ a^* = \arg\min_{a \in \{\mathrm{trust}, \mathrm{verify}, \mathrm{search}, \mathrm{retire}\}} \mathbb{E}[C_a] \]

这里 B_remain 不再直接用 min() 截断每个失败分支。 预算应作为可行性约束和日志诊断；如果把失败成本截断到剩余预算，系统会把“预算快耗尽”误解成“失败很便宜”，从而偏向 trust 一个几乎失效的记忆。 这不是全局 POMDP，只是对当前 query 相关 top-K 记忆做低频预算决策。

5.5 路径缓存失效推导

旧路径是否仍可用，不能只看障碍物本体是否碰到路径中线。 Nav2 的 inflation layer 可能已经让走廊不可通行。因此定义：

\[ R_{\mathrm{changed}}^{\mathrm{inflated}} = \operatorname{dilate}\left( R_{\mathrm{changed}}, r_{\mathrm{robot}} + r_{\mathrm{safety}} + r_{\mathrm{inflation}} \right) \]
\[ T_{\mathrm{path}} = \operatorname{dilate}\left( path, r_{\mathrm{robot}} + r_{\mathrm{tracking}} \right) \]

若：

\[ R_{\mathrm{changed}}^{\mathrm{inflated}} \cap T_{\mathrm{path}} \neq \emptyset \]

则缓存路径代价失效，需要对 finalist 重新调用 planner 或局部 A*。

7. 怎么落地到当前项目

  1. 先扩展 core model：加入 p_existence、p_location_valid、p_usable、retired_reason。
  2. 扩展 SQLite：新增 memory evidence 表，记录 POSITIVE / NON_CONFIRMATION / OCCLUDED / UNKNOWN / ACCESS_BLOCKED。
  3. 在 Phase 1A deterministic runner 中先做无 RGB-D 的版本：用 non-confirmation 和 access-blocked 更新 usability。
  4. 再接 synthetic replay：模拟 FREE / OCCLUDED / UNKNOWN，验证状态转移。
  5. 从 XJTLU 真车仓采集 RGB-D / RTK / costmap / Nav2 trace，离线 replay 后再做小规模闭环。
第一版不要直接上实车闭环。应先采日志、离线 replay，然后再做小规模真车闭环。

8. 验证计划

阶段要证明什么核心指标
Deterministic simulation 状态机和 belief 更新不犯基本错误 retire/revive 正确，单帧不误删
RGB-D trace collection 真实传感器下 FREE/OCCLUDED/UNKNOWN 比例 深度孔洞、bbox 抖动、non-confirmation 频率
Trace-driven replay 算法比 naive/aggressive/conservative baselines 更少白跑和误删 false deletion、false write、wasted navigation

9. 风险与边界

风险为什么危险设计回应
FREE 很少出现 系统可能一直 UNKNOWN FREE 不是唯一负证据；non-confirmation 和 access failure 也降低 P_usable。
延迟晋升不够新 MOT 已有类似机制 论文重点不是 tracking，而是 navigation usability belief 和 retire 决策。
类别衰减变调参表 泛化性差 只用粗类别先验，主要靠事件驱动 hazard。
路径缓存过期 箱子在边缘也可能通过 inflation 堵路 使用 inflated changed region 与 path tube 检查。
OOD 传感器故障 坏深度可能批量清空记忆 批量异常进入 quarantine，冻结负面更新。

10. 论文贡献表述

  1. Usability-centered memory belief： 将长期物体记忆拆成 existence、location validity、navigation usability， 避免把“可能存在”误当作“值得导航”。
  2. Event-driven usability retirement： 即使无法获得强 FREE 证据，系统也能根据 non-confirmation、access blocked、 persistent occlusion、scene change 让幽灵记忆退出默认决策。
  3. Budgeted trust / verify / search / retire policy： 用有限预算期望成本选择动作，并用 inflated path-tube cache invalidation 保证路径代价不过期。
这条路线的承诺不是“我知道世界真相”，而是“我让长期记忆在不可信感知下仍然对 ObjectNav 有用，并减少灾难性误用”。
