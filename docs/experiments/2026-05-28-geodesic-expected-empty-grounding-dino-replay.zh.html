长距离 Expected-Empty Grounding-DINO Replay 报告

这次把官方 ObjectNav episode start 到 goal 的长距离 navmesh replay， 和 expected-empty stale-memory 验证合在一起跑。配置使用 Grounding-DINO、1280x720、RGB/depth noise、memory on / naive_count / off。

commit: 937e47c host: badger-linux conda env: habitat dataset: HM3D ObjectNav val_mini detector cap: 384 protocol: geodesic_expected_empty_challenge

1. 结论

现在有一条可复现的长距离 replay 结果了。 EPC2 矩阵里，memory=on 和 naive_count 都是 17/18 successful episodes。memory 的 raw trust 更少：240 vs 256，平均首次成功路径略短： 13.344742m vs 13.471588m。

但这还不是“算法碾压 baseline”。naive_count 的 gated success rows 更多：136 vs 117。当前最诚实的 结论是：memory 在 stale trust 安全性上更稳，成功 episode 不输； 但在 replay row 数量上仍偏保守。顶会级主张还需要 object-instance anchor 持久化和 action-level navigation。

2. 做了什么

新 replay 协议

geodesic_expected_empty_challenge：

official episode start → navmesh waypoints → goal confirm → expected-empty hidden view → revisit。

关键修正

FOV geometry gate 只在 expected_empty 和 revisit 阶段做 anchor 验证，避免 early approach positive 污染锚点后误杀真阳性。

恢复阈值

current-positive recovery threshold 从 0.88 调到 0.84，但 shared gate 仍要求当前目标可见且 detector positive。

6. 当前状态

  • 已完成：Grounding-DINO category qualification、短 expected-empty、bed PNG 诊断、FOV geometry gate、长距离 expected-empty replay。
  • 仍不足：当前还是 replay，不是 action-level Habitat ObjectNav；指标是 oracle-stop rows，不是 SPL。
  • 算法还不够强：memory 成功 episode 不输，raw trust 更少，但 success rows 没超过 naive_count。
  • 主要风险：plant heavy detector miss、object-instance anchor 还没有 SQLite 持久化、没有真正多房间生命周期移动/删除场景。

7. 下一步

  1. 实现 object-instance anchor persistence：把 per-replay geometry anchor 升级成 SQLite 中的对象实例锚点，带观测计数和不确定性。
  2. 做真正 lifecycle 场景：跨房间/走廊 confirm → expected-empty → search/reacquire/retire，而不是只在单 episode 内 replay。
  3. 接 action-level Habitat follower，报告路径长度、stop action、SPL-like 指标。
  4. 继续保持 naive_count 朴素：只数 positive，不吸收 non-confirmation、geometry、delayed birth 或 persistence。
