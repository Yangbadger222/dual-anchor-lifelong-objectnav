1. 一句话结论

跑完了。 在固定 replay 轨迹上，memory on 能把重复检测证据累积成 TRUST，产生 268 个 oracle-stop success row； memory off 是单帧基线，永远停在 VERIFY， success row 为 0。

这说明当前记忆更新和决策链路在 Habitat replay 里是通的，而且对 bed、sofa、toilet 很明显有用。 但它还不是完整导航结果，也不能直接写成 SPL 或 ObjectNav success。

2. 这次到底跑了什么

轨迹

固定 out_and_back：reset + 14 个 Habitat action， 每个 replay 产生 15 行 trace。使用 --no-stop-on-trust， 即使已经 trust 也继续走完轨迹。

检测器

Grounding-DINO IDEA-Research/grounding-dino-tiny， Habitat render 是 1280x720，检测器侧 resize cap 是 384，这是 RTX 4070 Laptop GPU 上当前能稳定跑的配置。

矩阵

5 类别 x 2 episode x 3 noise level x 2 memory mode = 60 个 replay-run，900 行 trace。

本轮类别是 bed、sofa、toilet、 plant、tv_monitor。chair 暂时没放进主矩阵，因为前一轮 qualification 显示 first-N chair episode 主要卡在目标不可见，不适合拿来评价 memory。

这里要特别注意：memory off 不是“同一个 episode 内还可以累积， 只是跨 episode 不保存”的基线。当前实现是每一帧都从 INITIAL_BELIEF 开始，只吃当前帧证据，所以它是严格单帧基线。 单帧 positive evidence 会让 p_valid 到约 0.76，但策略仍选择 VERIFY，不会到 TRUST。

因此这个结果能说明：重复证据累积对 replay 里的 trust 决策有明显作用。 它还不能单独说明：跨 episode lifelong memory 比 episode-local memory 强多少。

9. 下一步建议

  1. 加一个 episode_local ablation：episode 内累积、episode 间不持久。 这样才能拆开“短期证据累积”和“lifelong 跨 episode memory”。
  2. 给 stop/trust 加 current-view confirmation gate，尤其约束 tv_monitor 和 plant。
  3. 做 visibility-aware episode selection，再把 chair 加回矩阵。
  4. 导出 false-trust debug PNG，把错误分成 detector false positive、 oracle sparse visibility、几何/遮挡三类。
  5. 最后再接 Habitat follower 或真实导航系统，报告真正的 navigation metric。
