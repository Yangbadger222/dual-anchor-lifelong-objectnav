1. 一句话结论

新矩阵跑完了。 shared gate 把 raw TRUST 从 694 行压到 gated TRUST 488 行，主要拦掉了 tv_monitor 和 plant 的 out-of-view false-trust。但当前 fixed replay 还没有证明 Dual-Anchor/Lifelong memory 优于朴素 naive_count。

当前最准确的结论是：正证据累积很有用，shared gate 是必要的； 但这个 replay 任务太容易被朴素 positive-count baseline 解释掉。 下一步要设计一个 naive-count 会失败、而 Dual-Anchor 应该赢的任务。

2. 这次跑了什么

轨迹

固定 out_and_back：reset + 14 个 Habitat action， 每个 replay 15 行 trace。使用 --no-stop-on-trust， 让 trust 后的 gate 行为也能被看到。

检测器

Grounding-DINO IDEA-Research/grounding-dino-tiny。 Habitat render 是 1280x720，检测器侧 resize cap 是 384。

矩阵

5 类别 x 2 episode x 3 noise level x 3 memory mode = 90 个 replay-run，1350 行 trace。

类别仍是 bed、sofa、toilet、 plant、tv_monitor。chair 继续等待 visibility-aware sampling。

off 仍然只是 lower sanity check。主对照现在是 naive_count：它只数 positive，两个 positive 后才过 trust 阈值， 不使用 non-confirmation、unknown、几何、延迟出生或跨 episode memory。

在这个 fixed replay 任务里，naive_count 和 memory on 很接近。这意味着当前实验只能支持“累积有用”， 还不能支持“Dual-Anchor 优于朴素累积”。

8. 当前状态

已完成

  • 三档 memory replay matrix 完成。
  • shared decision gate 生效，并写入 raw/gated trace。
  • naive_count 不再是单帧 baseline。

目前结论

  • 可以 claim positive accumulation matters。
  • 可以 claim shared gate reduces false-trust reporting。
  • 不能 claim memory-on beats naive-count。

主要风险

  • 当前 replay 任务对 naive-count 太友好。
  • tv_monitor 可见行太少。
  • plant 仍需 debug detector/visibility 细节。

9. 下一步建议

  1. 设计 naive-count 会失败的任务：跨 episode persistence、scene-change、negative evidence 或 geometry consistency。
  2. 导出 plant 和 tv_monitor gate rejection debug PNG。
  3. 做 visibility-aware episode selection，再把 chair 加回来。
  4. 接 Habitat follower 或真实导航系统之前，不要把当前结果写成导航成功率。
