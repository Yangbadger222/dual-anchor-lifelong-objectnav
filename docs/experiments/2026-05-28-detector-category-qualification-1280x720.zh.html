1280x720 YOLO-World Detector Category Qualification 报告

本报告说明我在 Linux Habitat 环境中做了什么、为什么改成正常分辨率、 detector category qualification 跑出了什么结果、目前算法能支持哪些类别， 以及下一步该先修什么。

1. 当前结论

可以进入主实验的类别

bed、sofa、toilet。

这三个类别在 clean RGB、target-conditioned YOLO-World prompt、 1280x720 输入下已经能触发 positive evidence 和 trust/stop。

可用但视角敏感

toilet。

stop-on-trust 语义下能成功；full trace 会继续走到更差视角， 导致后续 belief 被低质量视角稀释。因此 ObjectNav stop 语义是必要的。

暂时不能直接进全矩阵

plant、tv_monitor、chair。

plant 和 tv_monitor 是 detector/visibility blocker； chair 主要是当前采样 episode 缺少稳定可见目标，不适合直接评价 detector。

总判断： 现在不要把 clean/mild/heavy x memory on/off 全矩阵直接跑在所有类别上。 先用 bed、sofa、toilet 做第一版主实验； 同时补 visibility-aware episode selection 和失败类别 debug PNG。

2. 什么是 Detector Category Qualification

这里的 clean detector category qualification 不是最终算法指标， 而是一个前置资格检查：在没有 RGB 噪声的 clean 条件下，确认每个 ObjectNav 类别是否能被当前真实 detector 路径稳定看见并确认。

这么做的原因是：如果 detector 连 clean 可见目标都无法确认，后面的 memory 更新、noise robustness、sim-to-real claim 都会被 perception 失败污染。 资格检查把问题拆开：先问 detector/category 能不能用，再问 memory 算法在噪声下有没有帮助。

3. 为什么改成 1280x720

之前 64、96、224、320 都是 smoke-test 分辨率，用来快速找 pipeline bug。它们不代表真实相机输入， 也会让 YOLO-World 的小物体和边缘视角表现偏差很大。

本轮改成 1280x720，目的是模拟更接近真实 RGB-D 处理链路的输入尺寸： 不再用低分辨率解释 detector 失败，同时又比直接追求最高相机规格更适合批量 Habitat 运行。

注：本实验关心的是算法验证分辨率，不是声明某个硬件唯一分辨率。 真实部署时应以实际相机 stream profile 和算力预算为准。

4. 做过的代码工作

文件 改动 作用
habitat_objectnav_rgb_noise_stress.py 加入 sensor_width、sensor_height、sensor_size square override。 支持真实宽高比渲染；默认从 square smoke 转为 640x480，本轮显式跑 1280x720。
habitat_objectnav_rgb_noise_stress.py 加入 target_categories 与 episodes_per_category。 让 qualification 可以按类别均衡取 episode，而不是被数据集原始顺序带偏。
habitat_semantic_yolo_stress.py Simulator sensor resolution 支持 (height, width) tuple。 Habitat RGB/depth/semantic sensor 可以渲染非方形图像。
run_habitat_objectnav_rgb_noise_stress.py CLI 增加 --sensor-width、--sensor-height、--episodes-per-category、--target-categories。 Linux 上不改代码即可发起正常分辨率 qualification。
test_habitat_objectnav_rgb_noise_stress.py 补矩形分辨率解析、类别均衡选择、preflight summary 的测试。 防止以后又退回低分辨率或丢掉 category qualification 参数。

7. 我怎么看这个结果

  1. 分辨率问题已经基本排除。 本轮不再是 320 px smoke，1280x720 下仍然有明确类别差异： bed/sofa/toilet 能工作， plant/tv_monitor 不能。
  2. memory 算法链路没有被 perception 完全卡死。 detector positive 出现时，policy 会进入 TRUST， stop-on-trust 能形成 ObjectNav 风格成功行。
  3. 不能把 plant/tv/chair 的失败写成算法失败。 它们现在分别混有 detector category gap、目标过小/稀疏可见、episode 采样不可评价的问题。
  4. 下一步实验应该收窄类别。 第一版主矩阵先跑 detector-ready 类别，才能更干净地看 RGB noise 和 memory ablation 的关系。

  1. 把 full matrix 的类别先限制到 bed、sofa、toilet。
  2. 实现 qualification 的可见性筛选：每类选至少 N 个 reset/goal-viewpoint 上 oracle-visible 的 episode。
  3. 给 plant、tv_monitor、chair 输出 RGB + oracle mask + detector boxes PNG。
  4. 再决定是修 prompt/threshold，还是换更强 detector，然后重新 qualification。
