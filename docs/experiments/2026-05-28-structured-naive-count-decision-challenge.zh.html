结构化 Naive-Count 决策挑战报告

日期：2026-05-28；环境：macOS 本地；输出目录：runs/grid_trace/structured_naive_count_decision_challenge_seed17_ep900

一句话结论

在单房间 fixed replay 里，naive_count 和 memory 很接近；但在带场景变化、负证据、路径代价刷新和多同类歧义的结构化 trace 中，纯 positive 计数会明显积累 stale / ghost trust。当前结果支持继续往“多房间多走廊结构化 replay”推进，而不是继续只跑简单房间轨迹。

这次做了什么

  • 把现有 grid_trace_experiment 扩展为双策略输出：usability_memory 和 naive_count。
  • naive_count 保持最朴素：只累计 positive，两次 positive 后才允许 raw trust；不处理 non-confirmation、unknown、scene-change、delayed birth、JPDA 或 geometry。
  • 两条策略共用同一个 current-positive decision gate；报告同时保留 raw decision 和 gated decision。
  • 把 removed_or_moved 改成先出现两个 positive，再进入 non-confirmation / scene-change，这样 baseline 不是稻草人。
  • 生成了 JSON、CSV 和 HTML trace artifact，并新增了 Markdown 实验报告。

算法状态

现在的状态比前一版清楚很多：Grounding-DINO + shared gate 的 Habitat replay 证明 pipeline 能跑，但还不能单独证明 Dual-Anchor / Lifelong 优势；结构化 grid trace 证明在多房间/走廊会出现的 stale、blocked、association 类问题上，memory updater 和 association guard 确实有 naive positive-count 解释不了的收益。

这不是 Habitat SPL，也不是最终 sim-to-real 结果。它是决策逻辑压力测试，用来指导下一步该把什么结构搬进 Habitat 或真实 bag replay。

下一步

  • 把这个结构化挑战迁移到 Habitat：优先构造多房间/走廊 revisit、目标消失/重现、blocked access、nearby same-class distractor。
  • 继续保持 shared current-positive gate，三档策略都用同一个 gate。
  • 保持 naive_count positive-only、阈值为 2；不要给 baseline 加 non-confirmation、unknown、delayed birth、JPDA 或 geometry。
  • 检测器侧继续保留 0.70 面积过滤；剩余 tv_monitor false positives 需要 segmentation 或 appearance sanity check，不要靠更紧面积阈值硬砍。
  • 等结构化 Habitat replay 稳定后，再接 navmesh follower 或真实导航系统，报告导航指标。
