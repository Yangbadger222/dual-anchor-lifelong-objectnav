1. 一句话结论

算法链路已经跑通

在 sensor_size=320、yolo_prompt_mode=target、 stop_on_trust=true 下，YOLO-World 能确认可见 toilet， memory policy 能在可见目标上进入 TRUST，并触发 ObjectNav 风格 STOP。

还不是完整论文级结果

当前只是 clean smoke 与 6-episode 小 sweep。完整 clean/mild/heavy × memory on/off 矩阵还没有跑， plant 类在 YOLO-World 下仍然失败。

主要瓶颈在 perception/category

toilet 已经可用；plant 在多个 prompt 下置信度仍远低于 0.25。 这不是 memory updater 的失败，而是 detector/category/domain gap 需要单独处理。

2. 今天具体做了什么

  1. 在 Linux conda habitat 环境安装并验证 YOLO-World 依赖： torch==2.8.0+cu128、torchvision==0.23.0+cu128、 ultralytics==8.4.56、clip==1.0。
  2. 运行 oracle-bbox wiring smoke，确认 Habitat scene、RGB/depth noise、 semantic oracle、SQLite memory 和 policy 都能贯通。
  3. 运行 YOLO-World clean smoke，发现 64/96/224 分辨率下可见 toilet 仍然 0 检出；320 是第一个可用分辨率。
  4. 调试 YOLO-World 的 prompt 竞争问题：full 6 类 prompt 会把 visible toilet 区域高置信度标成 bed；改为 ObjectNav 目标条件 prompt。
  5. 修复 harness 语义：加入 stop_on_trust，一旦 policy 对可见目标 选择 TRUST 就停止 episode，避免继续走到边缘裁切视角后把 belief 人为打低。
  6. 加入 target view trace 指标： oracle_bbox、oracle_edge_sides、 oracle_touches_side_edge、oracle_edge_clearance_ratio。
  7. 做 6-episode 小 sweep：toilet 成功，plant 失败；进一步做 plant raw prompt probe， 确认不是简单 alias prompt 能解决。

Step 3 是一个很有用的诊断点：target bbox 同时碰到 right 和 bottom，属于侧边裁切； 这类帧不应该和完整目标视角混在一起评价 detector。STOP semantics 修复后，runner 不再继续走到大量 edge-clipped 后半段帧。

5.2 Plant 失败不是 memory 失败

Plant episode 中 oracle target pixels 很多，例如 reset 有 9148 pixels， 但 YOLO-World 在 plant / potted plant / indoor plant 等 prompt 下最高置信度仍远低于 0.25。 因此 memory policy 收到的是连续 non-confirmation，它下降 belief 是合理行为。

6. 算法结果如何

Usability / Dual-Anchor Memory

当前证据支持：当 detector 给出稳定正证据时，memory updater 能把 p_valid 推高，并触发 TRUST。

在 toilet STOP smoke 中，final p_valid=0.921945， 说明算法本身没有被 YOLO 接入破坏。

YOLO-World Perception

当前证据支持：YOLO-World 在 Habitat clean RGB 上可用于 toilet， 但不是所有 ObjectNav 类别都可靠。

Plant 连续失败，需要 detector/category 层面的补救，而不是继续调 memory。

Experiment Harness

当前 harness 已经从“能跑”提升到“能解释为什么跑成这样”： 它记录 prompt、view edge、STOP、belief 和 detector overlap。

完整矩阵仍需等 perception 先过 category qualification。

8. 下一步建议

  1. 先做 detector category qualification。 对每个 ObjectNav 类别跑 clean、target prompt、sensor_size=320， 每类至少 3-5 个 episode，输出 per-category success / recall。
  2. 单独解决 plant。 可尝试更大 YOLO-World 权重、GroundingDINO / OWL-ViT 对照、 GT crop prompt probe，或者把 plant 从第一轮 paper claim 的主结果里标为 detector limitation。
  3. 加入正式 debug PNG export。 现在 plant/toilet contact sheet 是临时脚本生成；应该把 missed-visible rows 的 RGB、oracle mask、detector boxes 作为 runner artifact。
  4. 改进 revisit sampling。 当前 out-and-back 是 deterministic action helper， 可以先加入 view-quality filter：侧边裁切过多的帧不计入 detector failure； 后续再做 navmesh-aware viewpoint sampling。
  5. 最后再跑完整矩阵。 等 clean detector qualification 过关后，再跑 clean/mild/heavy × memory on/off，否则矩阵只会测 detector failure。

10. 最终判断

当前最重要的判断是：算法验证已经从“无法开始”推进到“可以在合格类别上验证”。 YOLO-World 不再是完全检测不到 visible toilet；正确配置下，它能提供足够的正证据让 memory policy 做出 STOP/Trust 决策。现在真正的研究风险转移到了 detector category coverage，尤其是 plant。

因此，下一阶段不要急着跑全矩阵。应该先把 clean detector category qualification 做清楚， 再决定哪些类别进入主实验、哪些作为 detector limitation 报告。
